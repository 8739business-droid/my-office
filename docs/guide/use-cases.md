# 活用事例

職種の違う3人の例で、オフィスがどう育っていくかを紹介します。
(会話とフォルダは使い方のイメージです)

## 例1: 個人開発者(家計簿アプリを開発中)

**初回の回答**: 個人開発 / アイデアを忘れがち / 開発・技術

育ったオフィス:

```
my-office/
├── secretary/
├── creative/      ← アプリ名・ロゴ・バナーの依頼書(担当: アオイ)
└── engineering/   ← 設計メモとバグ調査(担当: リク)
```

## 例2: フリーランスの Web エンジニア(受託 + 自社 SaaS)

**初回の回答**: フリーランス / SaaS で月10万円を目指している・タスクが散らかる / 開発・技術、調べもの・リサーチ

- 競合の料金やオンボーディングを調べる依頼が続き、**リサーチ部(ミオ)** ができる
- 受託の請求書の話が出るたびに秘書室へ記録され、2回目で **経理部(ツムギ)** が提案される
- 「入金がまだの請求書」は、経理部のルールで秘書室の TODO にリマインダーが入る

```
my-office/
├── secretary/
├── research/      ← 競合調査(担当: ミオ)
└── finance/       ← 請求書と経費(担当: ツムギ)
```

## 例3: 副業で発信している会社員(ブログと SNS)

**初回の回答**: 副業 / アイデアを忘れる / 発信・集客

- 通勤中の思いつきは「メモ: …」で Inbox へ。その日最初に話しかけると、前回のやり残しも引き継げる
- 記事の企画や SNS の投稿の相談が続き、**マーケティング部(ハナ)** ができる
- 公開日が決まった記事は、マーケティング部のルールで秘書室の TODO にリマインダーが入る

```
my-office/
├── secretary/
└── marketing/
    ├── content-plan/   ← 記事・投稿の企画(status: draft → writing → review → published)
    └── campaigns/      ← キャンペーンと KPI
```

## 共通するポイント

- 最初から部署を作り込まなくていい。必要になったときに、ショーが声をかけてくれます
- 何を頼むときも、話しかける相手はショーだけです
- 記録は Markdown なので、エディタや Git でもそのまま扱えます
